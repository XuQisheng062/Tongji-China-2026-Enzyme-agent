Fixed Enzyme Agent：面向酶工程的多模型计算与工具编排软件
版本说明：截至 2026 年 9 月 27 日


一、从酶优化需求出发

酶工程中的候选设计需要同时考虑多个性质。一个突变可能在活性相关评分上表现较好，却不接近目标最适 pH；另一个候选可能更接近目标 pH，但稳定性预测并不理想。分别运行模型、整理不同格式的输出，再手动比较候选，会增加计算筛选中的操作负担。

围绕这一问题，我们开发了 Fixed Enzyme Agent，将候选突变构建、活性相关预测、最适 pH 预测、稳定性预测和可选的密码子优化组织到同一软件中。我们使用已有专业模型完成性质预测，由程序负责数据传递、候选筛选和执行校验，由 DeepSeek 负责自然语言需求解析、工具规划及结果解释。软件输出用于支持候选选择与后续实验设计，不替代酶学实验。

目前，我们提供固定流程在线版和可扩展的 Tool-based 版本。前者保留预设的计算顺序，后者允许使用者根据任务组合已注册工具。两种形式服务于不同的使用需求，并不是用自由规划完全取代固定流程。


二、固定流程：从蛋白质序列到候选结果

固定流程按预设次序组织三个模型。程序首先根据输入蛋白质构建单点突变候选，或者读取用户提供的突变 FASTA。EnzGFM 对候选计算活性相关代理分数并进行初步筛选；EpHod 预测候选的最适 pH；UniStab 提供稳定性相关预测。程序再结合用户目标，对这些指标进行综合筛选并输出候选。突变库由程序构建，EnzGFM 承担的是评分，而不是独立生成突变的功能。

在这一流程中，我们将目标 pH 纳入候选比较，避免仅依据活性相关评分排序。报告保留各项预测指标及排序依据，便于用户查看候选之间的取舍。activity_proxy 是模型代理分数，不被解释为实测酶活或成功概率；稳定性预测同样不等同于实测熔解温度。

为了支持连续探索，我们增加了可配置的多轮突变。默认运行两轮，每轮选取三个候选作为下一轮的母序列，重复相同的模型与插入工具顺序。用户可以调整轮数和分支数量。程序记录候选的来源及相对初始序列的累计突变，使报告能够呈现多轮形成的多位点变化，而不只显示最后一次替换。

用户还可以用自己的蛋白质 FASTA 突变库替代第一轮单点枚举。当前支持与参考序列等长、含一个或多个氨基酸替换的记录；突变描述由实际序列比较获得，不依赖文件标题中的突变标签。后续轮次仍从筛选出的母序列继续单点扩展。这使外部设计工具产生的候选能够进入现有筛选流程。

在推理实现上，我们调整了 UniStab 的调用方式，包括关闭推理阶段不需要的 gradient checkpointing、合并同一轮多个母序列对应的任务，以及移除推理时不需要的评估和绘图步骤。默认 batch size 保持为 1，以控制显存需求。这里的任务合并不意味着把多个序列同时放入更大的 GPU batch；我们没有将这些改动表述为已测得的固定倍数加速。


三、固定流程在线版与可扩展工具版

我们已将固定流程提供为在线版，作为预设酶优化链路的网页使用入口。在线版面向希望使用既定流程完成筛选的用户，不要求他们自行规划模型调用顺序。固定流程的用途是提供明确、可重复的执行路径，而不是让语言模型在每次运行中重新安排全部计算。

对于希望加入新模型、插入数据处理步骤或调整工具组合的使用者，我们提供可扩展的 Tool-based 版本。工具通过 ToolSpec 声明名称、能力、输入和输出，并由 Tool Registry 统一发现和管理。添加或移除符合契约的插件，不需要改写 planner 和 executor；固定流程也提供模型之间的工具插入位置，保留原有模型路径和核心次序。

DeepSeek planner 读取工具目录、用户需求和输入摘要，生成结构化任务路径。程序在执行前检查工具是否可用、能力与输入输出是否匹配，以及步骤依赖是否成立。未安装的工具不能被写入可直接执行的路径。规划结果同时区分系统内的可选工具和需要用户自行使用的外部工具建议，建议本身不会自动触发执行。

这一 planner 基于已有 DeepSeek API 和提示词调用，没有在本项目中重新训练语言模型，也没有通过强化学习训练工具选择策略。当前实现的自由度来自注册工具的可组合性和经过校验的规划，而不是已学习的最优调度策略。固定流程中的多轮突变能力与自由路径执行也有明确区别：自由路径不会自动继承固定流程的完整多轮候选扩展逻辑。


四、统一输入输出，减少工具之间的手工转换

为了让工具能够传递同一批候选及其预测结果，我们为自由路径中的模型工具定义了统一的 bioartifact/v1 契约。其内容包括序列记录、预测或表格数据、元信息和标准标签。工具适配器可以在内部生成模型需要的临时 FASTA 或 CSV，但对外仍返回统一的数据对象。

我们实现了 FASTA、CSV、JSON、GenBank，以及 SBOL XML 和 SBOL JSON-LD 的输入输出转换。用户文件在流程边界被标准化，计算完成后可按指定格式导出。不同格式的导出能力有区别：FASTA 适合传递序列，JSON 用于保存完整的内部数据对象，不能把仅包含序列的导出文件当作完整计算记录。

目前，GenBank 和 SBOL 的支持以序列互操作为主，不宣称无损保存所有注释、设计层级或关系。BioBricks/iGEM RFC 标识被作为标准元信息记录，不被当作一种独立文件格式，也不代表程序已经验证相应装配规范的全部要求。


五、连接候选筛选与表达设计

根据与湿实验方向交流获得的需求，我们在候选筛选之后加入了密码子优化，并将其封装为独立工具。用户指定表达宿主后，程序可以对野生型及最终候选进行同义回译，输出相应的编码 DNA 序列。

当前实现提供 11 种常用宿主的内置密码子偏好配置，包括项目关注的枯草芽孢杆菌。内置配置可以离线使用；对于其他宿主，程序提供基于物种信息查询 Kazusa 数据的补充路径，并记录无法获取数据的情况。

这一模块采用宿主偏好的同义密码子，不改变蛋白质序列。它没有同时优化限制性内切酶位点、重复序列、mRNA 二级结构等全部合成约束，也不能保证表达量提高。因此，输出的 CDS 是后续构建设计的输入，仍需要结合具体载体和实验条件检查。


六、最新版本：由可验证失败触发受限修复

当工具可以自由组合后，计划通过校验并不保证每次执行成功。模型可能超时、返回空文件或缺失预测值；计算也可能正常结束，却没有得到满足明确约束的候选。为此，我们增加了 Verifier-Gated Failure-Triggered Reflection，即由程序验证结果控制的失败触发反思机制。

验证器区分工具执行失败、非法参数、遗漏必需步骤、违反明确任务约束，以及可以由序列和结果直接判定的不一致。它输出失败类型、原因和证据，区分“调用是否有效”与“结果是否满足已配置目标”。只有验证失败、存在允许的修复且预算尚未耗尽时，才调用反思接口；通过检查的步骤直接继续。

LLM 根据证据分析失败，并从程序生成的修复选项中选择动作，例如补齐必需步骤、切换同能力的可用工具，或在配置上限内调整超时。它不能降低用户阈值、改写输入序列或编造预测值。成功步骤被保留，完全相同的失败动作不能重复，默认整次运行最多修复两次。无法修复或预算耗尽时，系统保留失败状态和日志，不将任务标记为成功。

该功能默认关闭，可通过 --reflection 开启。自由路径支持上述受限修复；固定流程保留原有筛选逻辑，目前主要在模型调用边界处理允许的超时修复，并在最终候选处检查明确目标。两条路径的修复范围并不完全相同。

运行过程保存结构化轨迹，记录工具调用、验证结果、反思与修复动作，便于定位错误和复查。轨迹保存不等于长期记忆；当前版本没有加入 memory 或 RL。验证器也不判断预测值是否等于真实酶学性质，未转换为结构化配置的自然语言约束不保证被完整检查。


七、我们完成的测试与得到的结果

早期服务器测试验证了 EnzGFM、EpHod 和 UniStab 在独立环境中由同一主程序调用的计算流程。在项目记录的一次目标最适 pH 为 7.5 的测试中，单轮前三个候选的预测最适 pH 分别为 6.7109、6.7853、6.9428；连续四轮后，前三个候选为 7.2414、7.3128、7.1893。最接近目标的偏差由 0.5572 缩小到 0.1872。

这个案例说明，多轮搜索在该次计算中找到了预测值更接近目标的候选。它不是多任务统计结果，也不能证明实际酶的最适 pH 或活性已经改善。采用少量父序列逐轮扩展还会遗漏其他突变组合，软件不保证得到全局最优解。

针对最新加入的验证与修复机制，我们于 2026 年 9 月 27 日完成了 59 项自动化测试，全部通过，并完成 Python 语法编译及仓库检查。此外，我们运行了 640 次离线故障注入任务，对比不进行反馈修复的 Baseline 与启用闭环的 VerifierReflection。实验覆盖工具异常、非法结果、参数错误和遗漏步骤四类故障，以及 0、0.1、0.2、0.3 四个注入概率。

这些实验使用确定性工具和反思测试替身，而不是真实 DeepSeek 或三个专业模型。以工具异常为例，故障概率为 0.3 时，Baseline 与 VerifierReflection 的最终成功率分别为 0.30 和 0.70；零故障时两者均为 1.00，且不触发反思。仍有修复失败和预算耗尽的情况。

离线结果用于检验故障检测、修复选择和停止规则，不是 planner 质量评测，也不是实际 LLM 反思能力或生物学效果的证明。完整数据位置与测试边界记录在 docs/verification_results.md。最新闭环在真实 DeepSeek 和 GPU 模型任务上的对照评测尚未完成。


八、复用、记录与发布边界

我们提供源代码、README、MIT LICENSE、示例配置、命令行入口、插件与文件契约说明、服务器运行指南和测试脚本。中文或英文需求可以进入语言接口，报告语言可配置为中文或英文。模型通过适配器在各自环境中运行，便于保留上游依赖，同时统一记录计划、模型日志和执行结果。

仓库检查脚本限制源代码及未忽略待提交文件的总体积低于 50 MB，并将模型权重、虚拟环境、缓存和大型运行结果排除在提交之外。该检查不等于已审计完整 Git 历史体积。项目已经提供 Dockerfile 和使用说明，但容器范围仅覆盖编排程序及离线实验，不包含三个模型的完整 CUDA 环境和权重；镜像构建运行、目标平台依赖锁定及官方 iGEM GitLab 发布尚需完成验证。

现阶段，我们完成的是一个连接多种酶工程计算工具、支持固定使用与扩展开发，并能记录部分失败及受限恢复过程的软件。下一步验证将围绕真实任务中的执行恢复率、额外调用与时间成本，以及候选预测与湿实验结果的对应关系展开。我们不将这些待验证内容写作已完成的性能或实验结论。
